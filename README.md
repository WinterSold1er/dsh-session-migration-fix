# dsh-session-migration-fix

DeepSeek Harness (dsh) bundle plugin that fixes format migration errors on historical sessions containing `thoughtSignature`, `textSignature`, or `thinkingSignature`.

## Problem

When updating DeepSeek Harness to the latest version, viewing historical sessions generated by certain models/providers (such as Gemini 2.0/2.5 via Antigravity or Google Cloud Code) can fail with:

```text
failed to observe session "session-...": @deepseek-ai/dsh-session-format-v0-to-v1 refuses this format v0 Session: assistant/message 30 message content[0] has unexpected member "thoughtSignature"; source v0 artifact remains unchanged (raw log: /home/.../session.jsonl.zstd)（gateway/internal）
```

### Root Cause

In earlier sessions, providers streaming tool calls from reasoning models (like Gemini) emitted `thoughtSignature` on chunk blocks. The `BlockAssembler` included this property directly on `ToolCallBlock` within `message.content` when writing session logs.

DSH session format migrations (`v0-to-v1`, `v1-to-v2`, `v2-to-v3`) enforce strict schema validation on content blocks (`['type', 'id', 'name', 'arguments']`). Any unexpected member causes the migration to refuse the historical session, preventing the Web UI from observing or resuming it.

## Solution

This plugin hooks `sessionPersistence.generationFormat.createRestore` at runtime. During historical session decoding and format migration, it automatically strips leaked `thoughtSignature`, `textSignature`, and `thinkingSignature` properties from content blocks and stream chunks, while keeping valid `source.replayState` metadata intact.

- **Non-invasive**: Zero modifications to DSH core source code.
- **Safe**: Source historical logs on disk remain unchanged unless explicitly migrated on write.
- **HMR-safe**: Disposes cleanly when the plugin is unloaded.

## Installation

Install into your target profile (e.g. `web`):

```bash
dsh plugin --profile web add WinterSold1er/dsh-session-migration-fix
```

Or directly via pnpm:

```bash
pnpm --dir ~/.dsh/profiles/web add github:WinterSold1er/dsh-session-migration-fix
```

Then restart the DSH host service (or restart `dsh`):

```bash
# If running as systemd user service:
systemd-run --user --on-active=2s --unit=restart-harness systemctl --user restart deepseek-harness-official.service
```
